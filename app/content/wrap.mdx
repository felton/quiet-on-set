## Building

`pnpm build` writes `build/client` (static assets) and `build/server` (the server-rendering app). Any host that runs Node can serve them with `pnpm start`, and the included `Dockerfile` packages the same build for container platforms.

## Static hosting

Without a server, React Router builds plain files that any static host can serve.

- **SPA mode:** `pnpm build:spa` writes a single `build/client/index.html`, and every route renders in the browser. Preview it with `pnpm preview:spa`. The host has to send unknown URLs to `index.html`; on Netlify that's a `_redirects` file containing `/*  /index.html  200`.
- **Pre-rendered:** set `ssr: false` and `prerender: true` in `react-router.config.ts` to get one HTML file per route, made at build time. That's better for first paint and search.

## GitHub Pages

This site is deployed exactly this way. It's pre-rendered and served from the project subpath, `https://felton.github.io/quiet-on-set/`.

1. **Config.** Set the subpath in both files. `basename` sets the route paths, and Vite's `base` sets the asset URLs.

   ```ts
   // react-router.config.ts
   export default {
     ssr: false,
     // Every static route, plus /404 for the catch-all route (see step 2).
     async prerender({ getStaticPaths }) {
       return [...getStaticPaths(), "/404"];
     },
     basename: "/quiet-on-set/",
   } satisfies Config;
   ```

   ```ts
   // vite.config.ts
   export default defineConfig({
     base: "/quiet-on-set/",
     // ...
   });
   ```

2. **Flatten the output.** With a `basename`, React Router writes pre-rendered pages to `build/client/quiet-on-set/…`, but Pages serves `build/client` itself at `/quiet-on-set/`. A short post-build script moves the pages up next to the assets:

   ```json
   "build": "react-router build && node scripts/flatten-prerender.mjs"
   ```

   The same script turns the pre-rendered `/404` page into `404.html`, which Pages serves for any unknown URL. That page comes from a catch-all route (`route("*", …)`), so it also matches the unknown URL in the browser and hydrates without a mismatch. The script is [`scripts/flatten-prerender.mjs`](https://github.com/felton/quiet-on-set/blob/docs/scripts/flatten-prerender.mjs) on this site's branch.

3. **Workflow.** Build, upload `build/client` as a Pages artifact, and deploy it. Pull requests build but don't deploy. The full file is [`.github/workflows/docs.yml`](https://github.com/felton/quiet-on-set/blob/docs/.github/workflows/docs.yml).

   ```yaml
   - run: pnpm install --frozen-lockfile
   - run: pnpm build
   - uses: actions/upload-pages-artifact@v5
     with:
       path: build/client
   # then, in a job with `environment: github-pages`:
   - uses: actions/deploy-pages@v5
   ```

4. **Settings.** Under **Settings → Pages**, set **Source** to **GitHub Actions**. If you deploy from a branch other than the default one, also add it under **Environments → github-pages → Deployment branches and tags**.

## Other hosts

The pre-rendered or SPA `build/client` folder works on any static host (Netlify, Cloudflare Pages, S3, nginx). Deployed at the domain root, it needs no `basename` and no flatten step. For server rendering, deploy the default build to any Node host or as a container.

## Working with agents

The template is set up for coding agents as well as people:

- `AGENTS.md` lists the commands, the layout and the conventions. `CLAUDE.md` imports it.
- `.agents/skills/` holds the official React Router and shadcn/ui agent skills, symlinked into `.claude/skills/`.
- `pnpm check` is the bar for done, and CI runs the same command.
